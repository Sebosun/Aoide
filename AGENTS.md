# Project conventions

- Vue: use BEM class names (`block__element--modifier`) and `<style scoped>` wherever possible. Keep shared resets and theme tokens global.
- TDD: agree the public seam, then run one failing behavior test before the smallest implementation that passes it. Repeat in vertical slices; test public results rather than private helpers.
- EPUB parsing belongs in `crates/epub-parser`, independent of Tauri, UI, network, and speech generation. Run its Cargo tests without building the desktop app.
- Web articles: `crates/article` extracts from a stored snapshot, pure and deterministic like EPUB parsing; `crates/fetch` is the only network path, plain HTTP to public addresses (`Reach::Public`) with redirects checked hop by hop. Core tests script the fetcher (`Pages` in `src-tauri/src/core/article_tests.rs`); real-network tests are opt-in (`#[ignore]`, address from `AOIDE_TEST_ARTICLE_URL`). Feed and OPML parsing belongs in `crates/feeds`, pure like `crates/article`; feeds are fetched only through `crates/fetch` (`fetch_feed`).
- The optional browser: `crates/browser` drives Chrome or Chromium (`chromiumoxide` stays behind its API) and sends every request through its loopback proxy, which enforces `Reach`; core components are `core/browsing.rs` (start, idle, stop, rules), `core/browser_download.rs` (Chrome for Testing, pinned in `core/chrome-for-testing.toml`), `core/signin.rs` (the visible window) and `core/sites.rs`. Rule parsing and host matching are in `crates/config`. With `BrowserUse::Off` no browser is looked for, downloaded or launched; keep it that way. Core tests use `testing::ScriptedBrowser`; real-browser tests are opt-in (`AOIDE_BROWSER_TESTS=1`, program in `AOIDE_BROWSER`).
- Chatterbox protocol code belongs in `crates/chatterbox-client`. Test the public client over loopback HTTP with synthetic responses; real-server/GPU synthesis tests are explicit opt-ins. Keep production requests loopback-only, with proxies, redirects, and automatic retries disabled.
- Use tiny synthetic EPUB fixtures with original text in committed tests. Personal EPUBs stay outside Git; inspect only metadata, navigation, and bounded excerpts when establishing local regression expectations.
- Model anything with states as an explicit enum changed by one transition function over named events (as in `src-tauri/src/core/preparation.rs`); views render that stage.
- Core features are components: their own module under `src-tauri/src/core/`, owning their state and locks, reaching the rest of the app through a host trait `Core` implements, and tested beside it without a `Core`. `Core` builds, wires and forwards. Details in `docs/core-refactor.md`, section Component.
- `src/api/contract.ts` is generated from the Rust types, `CoreEvent` and the `#[tauri::command]` functions in `src-tauri/src/commands/`. After changing a type that crosses IPC or a command, run `AOIDE_WRITE_CONTRACT=1 cargo test -p aoide contract`. The mock serves views the core made (`src/tests/fixtures/`); after changing one, run `AOIDE_WRITE_FIXTURES=1 cargo test -p aoide fixture`. Let the core decide (as fields of its views) rather than re-deriving its rules in the UI or the mock.
- Extraction is deterministic. Preserve uncertain content and expose warnings; report excluded sections and their reasons. Never modify source books.
- Logging: emit `tracing` events with a stable dotted `event` name and flat fields (`book` via `logging::book`, `took_ms`, `from`/`to`, `outcome`): one line per state transition (where its `next` is applied), external call and job step. Fields carry book ids and file names only. Library crates use the `tracing` macros; `src-tauri/src/logging.rs` owns the subscriber. Every new event gets a row in `docs/logging.md`.
- Reading logs: query with the `rg`/`jq` recipes in `docs/logging.md`. Start from the problems or by-kind recipe, narrow by `event`, `book` and time, and end every query with `| tail -n N` (N ≤ 100).
