# Code review, November 2026

A review of the whole app for structure: implicit state machines, god objects, functions that do
everything, code that should live in its own module, and duplicated UI. Each finding has a fix; the
fixes are committed in the order below. Performance is reviewed last, in its own section.

## Backend

| # | Finding | Fix |
|---|---|---|
| B1 | `src-tauri/src/lib.rs` is 1,200 lines: about 120 commands of every area in one file, and `run`'s setup (230 lines) mixes resolving folders, the Folio migration, smoke overrides and logging. | Commands move to `src-tauri/src/commands/`, one module per area. `run` keeps the builder; setup steps become named functions. The contract reads every command module. |
| B2 | `Core::start` is 200 lines that build twenty components and spawn a dozen background tasks, with `if background` repeated five times. `core.rs` has empty section markers left from the component refactor. `Core::play` decides recording or speech inline. | `Core::start` = `build` (components) + `spawn_tasks` (background work). The choice of what narrates a book becomes one function. Empty markers go. |
| B3 | `aoide-library`'s `Library` keeps books, progress, the audio cache, bookmarks, listening, details, collections, discovered files, lookups and stored values in one 1,200-line `lib.rs`. Migrations are one 270-line function whose latest version is a literal (`0..=12`) that must be changed by hand beside each new step. | One module per table group, as articles, feeds, recordings and sites already are. Migrations become a list of steps; the latest version is its length. |
| B4 | `core/recordings.rs` is 1,600 lines: stored rows, live state, decoding, the sync queue, the quick check, transcription, matching, storing, model downloads and layout. `transcribe_block` (190 lines) runs the quick check *and* a block, gated by `done == 0 && !checked`. | `core/recordings/` with `live.rs` (live state, queue, decoding), `steps.rs` (check, `quick_check`, `next_block`, matching), `attach.rs`, `speech_models.rs` (choice and downloads) and `layout.rs`. |
| B5 | Long single functions: `Playback::state` (110 lines, three return shapes inline), `encode_m4b` (160), `search_blocking` (130), `scan_blocking` (110). | Split each into named steps; `Playback::state` gets one function per session kind. |
| B6 | The browser driver keeps `Option<(Browser, bool)>`, the `bool` meaning "has a window", and every caller `expect`s the option. `Library.conn` carries a stale `allow(dead_code)`. | A named `Running { browser, visible }`; the driver hands out a guard mapped to the browser, so callers cannot reach a missing one. The allowance goes. |

## Interface

| # | Finding | Fix |
|---|---|---|
| U1 | 727 relative imports (`../../api`). | `@/` alias for `src/` in Vite, Vitest and TypeScript; every import uses it. |
| U2 | About forty components restyle `<button>` from scratch (`.signin__button`, `.pair__button--primary`, `.confirm__button--danger`, …) with the same height, radius and fills. | `UiButton` (variants `plain`, `primary`, `accent`, `danger`, `quiet`; sizes) used everywhere a pill button is drawn. |
| U3 | Cards are restyled per screen (`.storage__card`, `.item-page__card`, `.find__card`, `.feeds__card`, …): the same page fill, radius, padding and shadow. | `UiCard`. |
| U4 | Spacing, radii and control sizes are literals (`gap: 8px` 75 times, `10px` 48, `6px` 43; radii 10/14/16/22). | Spacing, radius and size tokens in `theme.css`; a style test keeps literals out of components. |
| U5 | Implicit state in stores: `stores/audiobooks.ts` keeps `scanning`, `pairing` and `adding` as three flags for one activity that is never two at once. | One `activity` value changed in one place; the flags are read from it. |
| U6 | The "one of a few" toggle (Page or Lines, Light or Dark, a range of days, a kind of item) is built four times, each with its own track and chosen style. | `UiSegmented`, a labelled group of toggle buttons. |
